# Каталог плагинов Panopticon

Panopticon показывает этот список в «Настройки → Плагины → Каталог плагинов…». Каталог — только список: код плагинов лежит в репозиториях их авторов, приложение скачивает его из релизов GitHub.

- `plugins.json` — плагины каталога.
- `stats.json` — скачивания и дата последнего релиза. Пересчитывается раз в сутки (`.github/workflows/stats.yml`), руками не правится.

## Как добавить плагин

1. **Плагин.** Соберите его из [шаблона](https://github.com/YuryBogdanov/OrgNotes/tree/main/templates/plugin). Как писать плагины — в [руководстве](https://github.com/YuryBogdanov/OrgNotes/blob/main/docs/plugins/README.md).
2. **Репозиторий.** Он публичный, в ветке по умолчанию лежит `manifest.json`. По нему приложение узнаёт последнюю версию, права и совместимость.
3. **Релиз.** На каждую версию — релиз GitHub с тегом `1.2.0` или `v1.2.0`, равным `version` манифеста. В релизе — ассеты `manifest.json`, `main.js` и, если нужен, `styles.css`. Шаблон делает это сам: `.github/workflows/release.yml` собирает плагин на тег.
4. **PR сюда.** Добавьте запись в конец `plugins.json`:

   ```json
   {
     "id": "my-plugin",
     "name": "Мой плагин",
     "author": "Имя Фамилия",
     "description": "Одной фразой: что делает плагин.",
     "repo": "owner/panopticon-my-plugin",
     "categories": ["planning"],
     "icon": "M4 4h12v12H4z"
   }
   ```

   Поля записи:

   - `id` — как в манифесте; строчные латинские буквы, цифры и «-»; не занят и не совпадает со встроенными (`calendar`, `hello`, `inbox`, `kanban`, `quarter-goals`, `theme-pack`).
   - `categories` — одна или несколько: `planning` (задачи и планирование), `view` (вид), `integrations` (интеграции), `export` (экспорт), `themes` (темы).
   - `icon` — необязательный путь SVG в квадрате 20×20, линией; рисуется цветом текста.

Проверку `.github/workflows/validate.yml` проходит каждый PR. Она смотрит, что:

- запись правильная;
- репозиторий публичный;
- в последнем релизе есть `manifest.json` и `main.js`;
- `id` и версия манифеста совпадают с записью и тегом;
- права известны приложению.

Затем мейнтейнер читает код плагина. Плагин не должен делать того, чего не объявил в правах: например, ходить в сеть без `net`.

## Обновления

Каталог про новые версии знать не нужно. Поднимите версию в манифесте и выпустите релиз с тем же тегом — приложение увидит её по `manifest.json` ветки по умолчанию и предложит «Обновить».

## Корпоративные плагины

Плагины, которым не место в публичном каталоге, ставятся по ссылке на git-репозиторий: «Каталог плагинов… → Установить по ссылке…». Нужный тег или ветка должны содержать собранные `manifest.json` и `main.js` — в корне или в `dist/`. Доступ идёт через git и ключи Mac пользователя.
